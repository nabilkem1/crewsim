# Epic H-M: Platform, Analytics & Job Management

## Epic H: Run Comparison

### WH-001: Side-by-Side Run Comparison
**Description**: As a policy designer, I want to select two runs and compare their metrics side-by-side.
**Acceptance Criteria**:
- *Functional*: Select two runs. Display KPI diffs (absolute and percentage).
- *UX/Responsive*: Two-column layout on desktop, stacked with toggle on mobile.
- *Accessibility*: Color-blind friendly diff indicators (arrows + text, not just red/green).
**Dependencies**: WF-001
**Design System Components**: Diff Table, Trend Arrows
**Technical/API Implications**: Client-side diffing of two `/api/runs/{id}/metrics` payloads.

### WH-002: Configuration Diff Viewer
**Description**: As an analyst, I need to know exactly what parameters changed between two runs.
**Acceptance Criteria**:
- *Functional*: Visual JSON/YAML diff of the `effective_config` for both runs.
- *UX/Responsive*: GitHub-style split or unified diff view.
- *Accessibility*: Textual summary of changed keys for screen readers.
**Dependencies**: WH-001, WG-002
**Design System Components**: Code Diff Viewer
**Technical/API Implications**: Integration with a diffing library (e.g., `diff-match-patch`).

### WH-003: Statistical Significance (CRN T-Test)
**Description**: As a data scientist, I need to know if the cost difference between two policies is statistically significant.
**Acceptance Criteria**:
- *Functional*: Display p-values and confidence intervals using paired CRN (Common Random Numbers) T-tests.
- *UX/Responsive*: Educational tooltip explaining the p-value context.
- *Error/Data*: Disable CRN test if the runs used different random seeds.
**Dependencies**: WH-001
**Design System Components**: Stat Significance Badge, Tooltip
**Technical/API Implications**: Call backend equivalent of `compare` command.

## Epic I: Reports & Artifacts

### WI-001: Artifact Browser
**Description**: As a user, I need to browse and download all files generated by a run (HTML, CSV, Parquet, JSON).
**Acceptance Criteria**:
- *Functional*: File tree or list view of generated artifacts per run.
- *UX/Responsive*: Iconography for file types. Click to view (if supported) or download.
- *Accessibility*: Keyboard navigation through the file list.
**Dependencies**: WF-002
**Design System Components**: File Tree, Icon set
**Technical/API Implications**: GET `/api/runs/{id}/artifacts` listing S3/local file paths.

### WI-002: Embedded Report Viewer
**Description**: As an analyst, I want to view Policy Report HTML directly in the web app.
**Acceptance Criteria**:
- *Functional*: Safely embed the Plotly HTML reports in an iframe or native component.
- *UX/Responsive*: Full-screen toggle for the report viewer.
- *Security*: Sandbox iframe to prevent XSS if HTML is unverified.
**Dependencies**: WI-001
**Design System Components**: Iframe Container, Fullscreen Toggle
**Technical/API Implications**: Serve static HTML artifacts with appropriate CSP headers.

### WI-003: Bulk Download Manager
**Description**: As a data engineer, I want to download all artifacts for local deep-dive analysis.
**Acceptance Criteria**:
- *Functional*: "Download All" button that streams a ZIP of all artifacts.
- *Performance*: Stream the zip generation to avoid memory spikes on the backend.
**Dependencies**: WI-001
**Design System Components**: Download Button, Progress Toast
**Technical/API Implications**: Backend ZIP stream API.

## Epic J: Job Management

### WJ-001: Job Queue & Lifecycle
**Description**: As a user running heavy simulations, I need to queue jobs without blocking the browser.
**Acceptance Criteria**:
- *Functional*: Jobs move through `created` → `queued` → `running` → `completed/failed`.
- *UX/Responsive*: Global job queue popover in the top navigation bar.
- *Resilience*: Browser closure does not affect job execution.
**Dependencies**: W0-001
**Design System Components**: Popover, Job List Item
**Technical/API Implications**: Background task worker (e.g., Celery/Redis) integration.

### WJ-002: Live Log Streaming
**Description**: As a developer, I want to see the stdout/stderr of a running simulation in real-time.
**Acceptance Criteria**:
- *Functional*: Terminal-like view streaming engine logs.
- *UX/Responsive*: Auto-scroll to bottom, toggle to freeze scroll. Monospace font.
- *Performance*: Limit DOM nodes for logs (virtualized list).
**Dependencies**: WJ-001
**Design System Components**: Virtualized Terminal Log
**Technical/API Implications**: WebSocket or SSE log streaming.

### WJ-003: Cancel and Retry Actions
**Description**: As a user, I need to stop a long-running job or retry a failed one.
**Acceptance Criteria**:
- *Functional*: "Cancel" button for running jobs. "Retry" button for failed jobs.
- *Error/Data*: Canceling issues a SIGTERM to the worker and marks status as `cancelled`.
**Dependencies**: WJ-001
**Design System Components**: Action Buttons, Confirmation Modal
**Technical/API Implications**: Job cancellation API hook.

## Epic K: Error Handling & Diagnostics

### WK-001: Contextual Error UX
**Description**: As a user encountering an error, I need to know What happened, Why, and What to do next.
**Acceptance Criteria**:
- *Functional*: Errors explicitly state failure stage (e.g., "Calibration Failed: Config Invalid").
- *UX/Responsive*: Error states preserve user input and offer recovery actions.
- *Accessibility*: Error messages linked to inputs via `aria-describedby`.
**Dependencies**: W0-001
**Design System Components**: Error Alert, Form Validation
**Technical/API Implications**: Standardized API error response format (RFC 7807).

### WK-002: Diagnostics Viewer
**Description**: As an advanced user, I need raw diagnostic output when the simulation crashes.
**Acceptance Criteria**:
- *Functional*: "View Diagnostics" toggle in error states to show stack traces and engine panics.
- *UX/Responsive*: Collapsible section, copy-to-clipboard button.
**Dependencies**: WK-001
**Design System Components**: Collapsible Panel, Code Block
**Technical/API Implications**: Capture unhandled Python exceptions in the job runner.

### WK-003: Recoverability Actions
**Description**: As a user, I want the system to suggest fixes for common errors (e.g., missing data).
**Acceptance Criteria**:
- *Functional*: If data validation fails, show a link to the Data Quality Report.
- *UX/Responsive*: Actionable buttons directly inside the error banner.
**Dependencies**: WK-001, WE-010
**Design System Components**: Actionable Alert
**Technical/API Implications**: Map specific error codes to recovery URLs.

## Epic M: Observability & Auditability

**Description**: As a sysadmin, I want to monitor the web UI and engine backend health.
**Acceptance Criteria**:

**Dependencies**: W0-001

**Description**: As a developer, I want to track how long jobs are taking to optimize performance.

- *UX/Responsive*: Time-series line chart.
**Dependencies**: WJ-001
**Design System Components**: Time-Series Chart
**Technical/API Implications**: Aggregate queries on the jobs table.

**Description**: As a security officer, I want a tamper-proof log of critical system operations.

- *Data Integrity*: Append-only store.
**Dependencies**: WG-006
**Design System Components**: Data Table
**Technical/API Implications**: Centralized structured logging.
